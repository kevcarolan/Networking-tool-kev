    Sensors

    Your own SNMP sensors: any value a device gives over SNMP (a UPS on battery, BGP peers, firewall sessions, a room temperature…), read with the hardware health every few minutes. A value past a threshold makes the device a warning, is an event and is emailed with the Monitoring alerts. Each sensor's readings and graph are in the device's window, under Health.

    How to set up a sensor
    1. Find the OID. The device's MIB (from the vendor's support site) names every value. Look for the object you want, e.g. upsAdvBatteryCapacity, and its number. A value on its own ends in its instance, usually .0; a table column (one value per port, peer or sensor) is the column's OID without the row.
    2. Check it from this server (Ubuntu, package snmp): 
      snmpget -v3 -l authPriv -u USER -a SHA -A AUTHPASS -x AES -X PRIVPASS DEVICE 1.3.6.1.2.1.33.1.2.4.0
snmpwalk -v3 … DEVICE 1.3.6.1.2.1.15.3.1.2        # a table column: one line per row
snmptranslate -On UPS-MIB::upsEstimatedChargeRemaining.0   # a name to numbers (needs the MIB file)
      With v2c: snmpget -v2c -c COMMUNITY DEVICE OID. If it says No Such Object, the device doesn't have it (another model or release), or the SNMP view leaves it out.
    3. Choose how to read it: Value for a number as it is (temperature, %, sessions; Scale 0.1 for tenths); Rate for a counter that only goes up (errors, packets: shown per second); State for a status code: list the codes that are fine (the MIB says what each number means), and any that are only a warning. Anything else is critical.
    4. Thresholds (Value and Rate): warn or critical above or below. Leave empty what you don't need.
    5. Which devices: a platform, a site, or chosen devices; or leave all empty for every SNMP device. Devices without the OID show the sensor as unknown, so keep it to the devices that have it.
    6. Test on a device before saving: it reads the value now with the device's SNMP profile.
