A tool that holds your device logins should be hard to get into

It keeps credentials for every switch and firewall you own, so we designed it to stay inside your network and to change nothing on a device without a person deciding to.

Where it runs

Inside your network, on your server

No cloud, no call home

There is no hosted part to the product. The server makes no connection to the internet unless you connect a Cisco Meraki organisation, and its firewall blocks outbound traffic by default.

Works air-gapped

It installs from one offline bundle: the application, every Python package and the Ubuntu packages it needs. Nothing is downloaded on the server.

Checked before it installs

Each bundle comes with a SHA-256 checksum, which the installer checks before installing anything, and a list of every package and version in it for your change ticket. Every bundle is checked for known vulnerabilities when it's built.

Offline licences

A licence is a signed file pasted into the settings page and checked on the server. No licence server, no phone-home, no usage reports.

Towards your devices

Read-only unless a person starts a change

Read-only checks

Backups and version checks send only show commands. Monitoring uses ping and SNMP reads; it never sends an SNMP SET.

Upgrades need a person, a window and passing checks

An upgrade only runs when an admin with upgrade rights starts it, inside a maintenance window, after the pre-checks pass and the device's name has been typed to confirm. Each platform must also be switched on for live upgrades in the server's own settings.

Images are pushed, never pulled

Firmware is sent from the server over SSH or the device's own API. No device is ever told to fetch anything.

SSH host keys checked

Each device's SSH key is recorded the first time and checked on every connection after, so a device that's been swapped or spoofed is noticed.

People and data

Who can see and do what

Your directory

Active Directory over LDAPS, local users, or both, with two-factor sign-in from any authenticator app, and a break-glass admin for when the directory is down.

Permissions per area

View, change or manage, separately for inventory, backups, firmware, upgrades, circuits, syslog and monitoring. Seeing configs and using credentials are permissions of their own.

Secrets encrypted

Device passwords and SNMP keys are encrypted in the database. Lines that look like secrets are never shown in alerts or reports.

An activity log

Every change made through it is recorded with who, what and when, and the server can forward its own logs to your SIEM.
